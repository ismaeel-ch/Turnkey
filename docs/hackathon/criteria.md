# Hackathon rules and scoring: where this entry stands

Source: the Agent-A-Thon 2026 kickoff deck (26 Nov 2026) and the portal's rules and guide pages. The docs-architect
agent keeps this page current; the compliance-auditor checks it after each milestone.

## Dates

- Build window opens: Fri 27 Nov 2026, 12:00 AM PKT
- Submissions close: **Mon 30 Nov 2026, 2:00 PM PKT** (the latest submitted version is the one evaluated)
- Submit: GitHub repo URL, live production URL, summary of up to 600 characters

## How to read this page

- **Live app** is https://turnkey-bay.vercel.app/. Nothing needs a login. The title bar has a **Live** switch; with
  it off (Demo) every build replays a saved run and no model is called, so an evaluator can see every screen without
  spending budget.
- **Built** means in `main` and covered by the browser checks (12 flows in `tests/e2e`, run in CI before every merge), or covered by unit tests for server code. Updated 26 Nov
  after release v0.3.2: everything below is built unless a row says otherwise. This page is updated in a follow-up pull request when those merge.
- Where an evaluator looks: the app's top-level tabs are **Build**, **App**, **Release** and **Details**. Under Build
  the switch **Workflow / Timeline / Log / Meeting** shows the same run four ways. **Debug mode** (Settings, or the bug icon in
  the title bar) opens the event, tool-call, model-usage, SQL and API-call tabs. The orchestration diagrams are in
  [`docs/architecture/overview.md`](../architecture/overview.md).

## Step 2: the five criteria (1 to 10 each, equal weight)

### 1. Completeness, including multi-agent orchestration

What judges look for: works end to end; agents with distinct roles that hand work to each other and check each other;
each agent's steps shown.

| Evidence                                                                                                                                                                                                                                                                                                                                 | Where                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Distinct roles: Researcher, Database, Backend, View advisor, UI, Tester. The Orchestrator is code that runs them in order.                                                                                                                                                                                                               | `src/workspace/line.ts` (`AGENTS`, `STATIONS`), `tester.tsx`. Build tab, Workflow.                                                                                                                      |
| Handoffs: each agent receives the validated output of the ones before it (the brief, then the tables, then the rules, and so on).                                                                                                                                                                                                        | Sequence diagram, overview section 3. Build tab: arrows between nodes; the chat shows each handoff.                                                                                                     |
| Agents check each other: code checks after every station; a failed check sends the work back to the same agent with the failures in its prompt, at most three tries; the Tester's cases fail the Backend's work and the Backend repairs it.                                                                                              | `line.ts` (`runStation`), `tester.tsx` (`runTester`). Open "Sales bidding desk": its Backend answer keeps one planted slip so the repair is visible in Demo (`REC.biddesk.slip`). Build tab, **Tests**. |
| Human in the loop: a question card from the Researcher, approval gates the owner places after any station, approval before a change that deletes data, and a pause in the debate and bidding teams.                                                                                                                                      | `custom.tsx` (`askGate`), `changes.ts` (`askApproval`), `team.tsx` (`teamWait`). Build tab, **Customize**.                                                                                              |

### 3. Creativity and uniqueness

| Evidence                                                                                                                                                                                                                | Where                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| The product is the tool that builds agent apps, not one agent app. The three suggested quests, a bidding desk and a grant review desk are built by it and come out as separate working apps with their own agent teams. | Home screen: the saved builds. `quests.ts`, `builds.ts`.      |
